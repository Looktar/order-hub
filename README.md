# 订单协作（order-hub）

销售、公司、司机三方，加上各自的 AI Agent，共用一套订单系统。

```
销售提交订单 → 公司审核、修改、派给司机 → 司机送货（现场可改单）→ 拍签收照片确认送达
```

- 网页：https://looktar.github.io/order-hub/ （手机、电脑都能用）
- Agent 接入：见 [AGENTS.md](AGENTS.md)
- 第一次部署：见 [docs/部署设置.md](docs/部署设置.md)

## 怎么用

**销售**
- 点"新建订单"，拍订单照片，填写货品（机油、机油滤芯、轮胎、轮毂）、数量和送货信息，然后点"发回公司"。
- 也可以直接把订单照片发给你的 Agent，让它识别后代为提交。
- 订单被公司或司机修改、派给司机、送达、送货出问题时，你会收到通知（右上角铃铛）。
- 公司开始处理之前，可以修改自己的订单。

**公司**
- 首页是调度看板，按"待公司处理 / 已派给司机 / 送货中 / 已送达"分栏。
- 打开订单可以修改内容（必须写原因）和派给司机。
- 左边可以筛出被修改过的、今天要送的、送货有问题的订单。

**司机**
- 首页是派给你的送货单。打开后可以导航、打电话。
- 出发时点"开始送货"；到了现场，客户临时要改数量就点"修改订单内容"（要写原因）。
- 拍签收照片，再点"确认送达"。遇到问题点"送货有问题"。

**通知规则**：订单被修改时，只有公司和这张订单的销售会收到通知，其他销售和司机收不到。所有修改都会永久记录：谁改的、通过哪个 Agent、原来是多少、改成多少、为什么改。

**Agent 令牌**：在"设置 → 我的 Agent 令牌"里生成，交给你的 Agent，它就能以你的身份操作，权限和你本人一样。令牌丢了就作废重新生成。

## 技术说明

| 部分 | 位置 |
|---|---|
| 数据库结构、行级权限、所有写操作 | `supabase/migrations/` |
| Agent 接口 | `supabase/functions/api/index.ts` |
| 网页 | `web/` |
| 权限与通知测试 | `tests/`（`tests/run_local.sh`，需要一个空的 Postgres） |
| 自动测试和部署、保活、备份 | `.github/workflows/` |

所有写操作都在数据库函数里检查角色和订单状态，并在同一个事务里写修改记录和通知接收人；表本身不允许直接写入。Agent 通过接口调用时，接口先把身份切换成令牌对应的用户，再执行同样的数据库函数，所以 Agent 不可能比它的用户权限更大。
